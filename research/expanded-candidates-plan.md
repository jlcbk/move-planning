- 计划制定日期：2026-07-24
- 通勤终点：北汽蓝谷新能源科技股份有限公司，北京经济技术开发区（亦庄）东环中路5号（[公司官网地址](https://www.bjev.com.cn/about/contact.html)）
- 参考坐标：公司约 116.529, 39.793（沿用既有 OSRM 路线样本口径；若接入高德可用 `amap_geocode` 复核）

本文件只是**执行计划**，不产出结论。真正的大规模调研在 API 负载较低时按本计划分批开启，产出写入 `research/` 下对应文件与 `data/candidates.csv`。

> **当前执行口径（2026-07-24 更新）**：高德地图 MCP（AMAP_KEY）暂不接入。本轮默认用**距离与通勤估算**——OSRM 公开路网 + 房产平台小区页 + 地图网页查询——来定位坐标、估算里程与通勤，并在报告中一律标注"为估算，非实时高峰"。下文凡提到 `amap_*` 工具处，均为**高德可用时的增强路径**；不可用时按各节标注的"估算兜底"执行，不阻塞调研。

## 一、本轮目标相对首轮的变化

首轮以国风美仑为基准盘、马驹桥为中心。本轮按家庭最新意向放宽和调整搜索范围：

| 维度 | 首轮口径 | 本轮口径 |
|---|---|---|
| 地理范围 | 以马驹桥/亦庄为主的少数已知片区 | **开车30分钟内**全部可达片区，离公司或近或远都可以 |
| 房龄 | 未强制 | **2010年后建成**（电梯社区、管线与户型更新） |
| 生活便利 | 有提及 | **明确列为筛选目标**：买菜、医疗、商业、儿童活动 |
| 候选来源 | 人工列举的 6 个片区 | **按扇区系统性枚举**，不预设名单（默认地图网页/平台片区页，高德接入后用 POI 搜索） |
| 工具 | OSRM 理想路网 + 房产平台 | 默认沿用**估算**（OSRM + 平台 + 地图网页）；高德地图 MCP（hermes-china-services）作为接入后的增强项 |

幼儿园可进入性、停车、租赁合法性等**签约前一票否决项不变**（见 [DECISION-MATRIX.md](../DECISION-MATRIX.md)）。但在本轮"广撒网发现"阶段，先不用幼儿园/停车卡死候选，而是先建立"2010年后 + 30分钟 + 面积价格达标 + 生活便利"的宽候选池，再进入既有的电话/实地否决流程。

## 二、硬筛选口径（初筛用）

一个小区进入候选池，需同时满足：

1. **房龄**：主力楼栋建成年份 ≥ 2010。高德 POI 不稳定提供建成年代，需用房产平台小区页（贝壳/房天下/安居客/幸福里）交叉核验，取"多数来源一致"的年份。
2. **通勤**：驾车从小区坐标到公司，**平峰单程 ≤ 30 分钟**，且早高峰（工作日 8:00 出发）推断 ≤ 40 分钟（对齐既有 40 分钟高峰否决线）。默认用 OSRM 路网里程 + 地图网页估算并加保守余量；高德接入后用 `amap_route` 复核。
3. **住房**：能检索到 ≥ 2 套「整租、建筑面积 ≥ 80㎡、挂牌月租 ≤ 5000 元」的在租样本。
4. **生活便利**：小区 1.5km 内可查到生鲜/超市、社区卫生服务站或医院、幼儿园各至少 1 个。默认用房产平台小区页/地图网页查证；高德接入后用 `amap_nearby` 复核。

任一项明显不满足则不进池；处于边缘（如仅 1 套达标房源、平峰 30–33 分钟）标为"观察"，不直接淘汰。

## 三、候选发现方法（如何找到"更多小区"）

不预设小区名单，改为**按扇区 + 锚点枚举**。以公司为圆心，按方位切分扇区，每个扇区选 1–2 个地理锚点（片区中心或地铁站），枚举锚点半径内的居住小区（默认地图网页/房产平台片区页；高德接入后用 POI 搜索），再逐个过滤房龄。

### 扇区与锚点（初步，执行时以实际枚举结果为准）

| 扇区 | 大致方位 | 行政归属 | 锚点示例 | 说明 |
|---|---|---|---|---|
| A. 经开区核心/亦庄老城 | 公司周边 | 经开区 | 荣京东街、荣华中路、地铁荣昌东街站 | 首轮已覆盖贵园/鹿海园/泰河园/南海家园，本轮补齐同片区 2010 后新盘 |
| B. 亦庄新城河西区 | 南/东南 | 经开区/大兴 | 地铁次渠站、亦庄火车站方向 | 2015 后新建集中区，房龄优势明显，通勤待实测 |
| C. 大兴瀛海/旧宫 | 西南 | 大兴区 | 地铁瀛海站、旧宫站 | 瀛海多新盘、停车较好；旧宫首轮偏淘汰，但可挑 2010 后个别小区复核 |
| D. 通州马驹桥/台湖 | 东/东北 | 通州区 | 马驹桥镇、地铁施园站/环球度假区方向 | 国风美仑同片区替代盘（富力尚悦居、珠江四季悦城等待枚举）、台湖新盘 |
| E. 西红门/旧宫西/亦庄北 | 西/西北 | 大兴/丰台边界 | 地铁西红门站、旧宫站西 | 偏西，30 分钟是否可达需先做通勤先验（OSRM/地图网页估算；高德接入后用 `amap_route`），超时则整扇区降级 |

> 上表小区/片区名为**待枚举的搜索方向假设**，不是已确认候选。执行时先在锚点周边枚举居住小区（默认用地图网页/房产平台片区页；高德接入后用 POI 搜索），得到实际小区清单，再逐个套用第二节口径。

### 发现步骤（每个扇区重复）

1. 把锚点转坐标（地图网页/OSRM 口径即可；高德接入后用 `amap_geocode`）。
2. 以锚点为中心、半径 2–3km 枚举居住小区（关键词如"小区""花园""家园""公寓""嘉园""府"），收集候选小区名 + 坐标。默认用地图网页/房产平台片区页枚举；高德接入后用 `amap_text_search` / `amap_nearby` 系统搜索。
3. 对每个候选：房产平台查建成年代，剔除 2010 前。
4. 保留项进入第四节的统一数据采集。

## 四、调研维度与工具映射

当前**默认口径**（未接入高德 MCP）与**高德接入后**的增强口径并列。默认口径已足以完成初筛发现，高德接入后主要提升通勤与周边配套的精度。

| 调研维度 | 默认方式（当前） | 高德接入后 | 采集内容 |
|---|---|---|---|
| 候选发现 | 地图网页 + 房产平台片区页枚举 | `amap_text_search` / `amap_nearby` | 锚点周边居住小区清单与坐标 |
| 坐标定位 | 地图网页取点 / OSRM 口径坐标 | `amap_geocode` / `amap_regeo` | 小区/公司坐标，供路线计算 |
| 通勤 | OSRM 理想路网里程 + 保守高峰余量（推断） | `amap_route`（driving，含实时） | 平峰与早高峰驾车时长/里程；必要时 transit 兜底 |
| 停车/医疗/买菜/幼儿园 | 房产平台配套页 + 地图网页周边查询 | `amap_nearby` | 小区 1.5km 内停车场、社区卫生服务站/医院、生鲜超市、幼儿园数量与距离 |
| 天气（可选） | 不采集 | `amap_weather` | 实地试跑排期参考，非评分项 |

无论用哪种口径，房产平台（贝壳/房天下/安居客/幸福里/58）都负责地图给不了的字段：**建成年代、挂牌房源样本、物业费、车位比、租赁付款周期**。报告里必须区分"地图事实 / 平台样本 / 分析推断"，与 [research/README.md](README.md) 规范一致；通勤若用 OSRM 估算，须显式标注"为理想路网估算，非实时高峰"。

## 五、每个候选的统一数据结构

沿用并扩展 [data/candidates.csv](../data/candidates.csv) 的字段，新增本轮需要的列：

- `candidate`（小区名）
- `district`（行政区）/ `education_admin`（教育管理口径）
- `build_year`（建成年份，2010+）
- `lng` / `lat`（坐标；估算口径取地图网页点位，高德接入后用 `amap_geocode`）
- `commute_offpeak_min` / `commute_peak_min`（平峰 / 早高峰驾车时长，标注为估算或实测）
- `commute_km`（里程）
- `rent_samples`（≥2 套 80㎡/5000 元样本摘要 + 抓取日期）
- `parking_note`（车位比/费用线索）
- `amenities_note`（1.5km 内买菜/医疗/幼儿园计数）
- `kindergarten_lead`（片区内公办/普惠园线索）
- `status`（researching / 观察 / 入围 / 淘汰）
- `key_risk` / `last_verified`

## 六、分批执行计划（供后续并行调研）

大规模调研按扇区分批，每批可交给一个子任务独立完成，互不依赖，便于在 API 负载低时并行开启：

| 批次 | 范围 | 产出文件 | 验收 |
|---|---|---|---|
| 批 0 | 前置校验：确认公司坐标、估算口径对齐（高德接入后可选做工具连通性验证） | 无（就绪确认） | 能用 OSRM/地图网页给出公司↔某已知小区的距离与平峰时长估算 |
| 批 1 | 扇区 A 经开区核心 | 追加至 `research/expanded-candidates.md` + CSV | ≥5 个 2010 后小区完成六字段 |
| 批 2 | 扇区 B 河西区 | 同上 | 同上 |
| 批 3 | 扇区 C 瀛海/旧宫 | 同上 | 同上 |
| 批 4 | 扇区 D 马驹桥/台湖 | 同上 | 同上 |
| 批 5 | 扇区 E 西红门/亦庄北（先验通勤，超时则降级） | 同上 | 先给出扇区可达性结论 |
| 批 6 | 汇总：去重、按 100 分矩阵评分、更新横向比较与推荐 | 更新 `housing-alternatives.md` / `CURRENT-RECOMMENDATION.md` | 输出新的入围/观察/淘汰名单 |

执行约定：
- **幂等去重**：以小区坐标 + 名称去重，避免跨扇区重复（如经开区/大兴交界小区）。
- **增量写入**：每批完成即提交，不等全部跑完；沿用协作者分支 → PR → 合并流程。
- **失败可续**：单个小区数据缺失（如查不到建成年代）标注为待核验，不阻塞整批。
